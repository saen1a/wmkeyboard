# Clipboard secrets refactor specStatus: Plan, PlanReview clean, awaiting operator go.Scope: WM Keyboard clipboard history, secrets, password-manager integration, Android 16/17 readiness.Non-goal: replacing Android's clipboard service. No app-facing provider role exists.## GoalClose the identified clipboard gaps so that secrets and passwords are:1. never written to the normal history file, its `.part` file or any corrupt artifact,2. never included in Android Auto Backup or Device Transfer,3. always marked with Android's sensitive flag when they reach the system clipboard,4. removed from memory when they expire, when history is cleared, when the service locks or when the process dies,5. never exposed in suggestions, search, logs, accessibility text or screenshots,6. still pasteable while retained and still available to password managers through standard inline autofill.Normal, non-sensitive clipboard behavior must stay unchanged, except that the conservative heuristic may classify a benign secret-shaped clip as sensitive. That precision cost is explicit: a benign clip may be masked or dropped, and the existing benign-token cases are an acceptance criterion. The flag, a secure field and an autofill source are authoritative; the heuristic never overrides them downward.## Scope boundaries- in scope: WM Keyboard clipboard history, secret classification and retention, system-clipboard writes, the sync and ConfigBackup clipboard boundary, password-manager inline autofill integration, and Android 16 and 17 readiness.- out of scope: replacing Android's system clipboard service, a persistent encrypted vault, Samsung One UI vendor clipboard internals, and non-clipboard keyboard features.## Request coverageR7 and R8 are cross-cutting process constraints; they are listed against every unit they govern. It exposes `copyText`, `copyHtml`, `copyUri`, `privateCopy` and the held-text lookup. It takes the current `EditorInfo`, secure-field state, active autofill package and explicit user action, derives `Sensitivity`, and calls the internal writer or private holder.- `ClipboardWriter` in `feature/ime/.../`: `internal` to the IME module. It takes a `Sensitivity`, never a bare boolean. It sets `EXTRA_IS_SENSITIVE` and a private self-write token, records the item in the normal store or `SecretMemoryStore`, and returns the token. It never logs content. Raw calls are rejected by an architecture test outside the writer and the allowlisted app UI/debug paths.- `KeyboardClipboard` in `feature/ime/.../`: reduced to an `internal` memory holder for the currently held private text and its expiry. Its public `copy` method is removed; only `ClipboardWriteGate.privateCopy` can create or clear a hold.- `SelfWriteLedger` in `core/content/.../clipboard/`: a bounded, time-limited set of tokens. The listener skips a captured clip whose token is present. The ledger also prevents a stale token from suppressing a later legitimate copy.- `ClipboardCapturePipeline` in `feature/ime/.../`: takes a `ClipData` snapshot on the main thread and processes it on a single-thread dispatcher. It does not re-read the clipboard off main.- `ClipboardClassifier` in `core/content/.../clipboard/`: replaces the current `ClipSensitivity` object as the one owner of the sensitivity decision. It receives the secure-field state as a parameter from `feature/ime`; it never reads IME state itself. The existing `ClipSensitivityTest` is kept and extended; `ClipboardClassifier` must not leave a second heuristic owner behind.- `ClipboardPolicy` in `core/content/.../clipboard/`: one source of truth for retention, masking, caps, pinning and private-copy rules.- `SecretMemoryStore` in `core/content/.../clipboard/`: process-memory TEXT/HTML secrets with TTL, no disk, no backup, no search index.
