## Inventory

| Component | Responsibility | Important type | Depends on |
|---|---|---|---|
| Key grid pointer loop | Samples one-finger and two-thumb strokes, claims a glide, publishes previews | `KeyboardScreen`, `ThumbStroke` | Compose pointer input |
| `FlickGlideArbiter` | Decides whether a stroke belongs to a flick arm, a glided word, or the key | `FlickGlideArbiter` | Key cells and arm geometry |
| `GlideDwell` | The ambiguity picker's clock: when a still finger has waited long enough | `GlideDwell` | Pointer samples |
| `GlidePreviewGate` | Holds the word already on screen against challengers, and makes a lift type the shown word | `GlidePreviewGate` | `GlidePreviewSteadiness` |
| `GlideSpace` | The spaces and punctuation a committed word earns, plus possessive and contraction flicks | `spacesBeforeGlidedWord`, `swallowsAutoSpace` | `WordContext` |
| `SuggestionEngine.glide` | The single decode entry: fold, sources, engine choice, finish, rerank | `SuggestionEngine` | Word sources, stores |
| `GlideBeam` | The built-in decoder's weights, results and façade over JNI | `GlideBeam`, `GlideBeam.Tuning` | `NativeGlide` |
| `NeuralGlide` | Maps a QWERTY stroke into the FUTO frame and runs a CTC search | `NeuralGlide`, `CtcGlideBeam` | `SwipeModel`, native CTC |
| `LatinImeGlide` | Adapts the imported AOSP gesture library and its own dictionary | `LatinImeGlide` | `LatinImeLibrary` |
| `DuetBeam` | Orders taps and swipes from two thumbs into one word | `DuetBeam`, `GlideToken` | Native duet search |
| `GlideOverhang` | Folds samples above the top letter row back onto it | `GlideOverhang.fold` | `GlideKeyMap.topEdge` |
| `GlideShapeStore` | Stores a few ways this user draws each word | `GlideShapeSource` | Learning files |
| `KeyOffsets` | Learns where this hand lands relative to the key centers | `KeyOffsets` | Learning files |
| `GlideOutcomes` | Remembers pairwise corrections and undone words as score nudges | `GlideOutcomes.View` | Learning files |
| `GlideSandboxLadder` | Measures whether learned-only decoding would serve this user | `GlideSandboxPolicy` | Learning files |
| `GlideCheckup` | Replays strokes under candidate weights and proposes one change | `GlideCheckup` | Learning files, settings |
| `GlideReadings` | Keeps the other readings of a glided word, tied to its caret anchor | `GlideReadings` | In-memory field state |
| `NativeGlide` | The only JNI call site for glide, CTC and duet decodes | `NativeGlide` | `PredictionNative` |

## Engine selection

The service picks one engine per decode from `GlideEngine`: the built-in
`GlideBeam`, FUTO's `NeuralGlide`, or the imported `LatinImeGlide`. An external
engine that cannot read the stroke returns `null`, and the built-in beam takes
the request. The built-in path returns an empty list for a stroke below its
minimum length and raises `NO_TWIN` when a source has no Rust twin; it never
returns `null`.

The conditions, build gates and the fallback flow live on
[Languages and engines](/development/glide-engine/languages-and-engines/#engines).

## Boundaries that matter

- **The service owns the session.** `gestureGeneration` invalidates a preview
  that arrives after a lift. A decode never mutates `KeyboardUiState` directly.
- **The engine owns ranking.** The service does not reorder candidates except
  through the documented gates: `GlideGuessGate`, the preview gate, and the
  commit case.
- **The stores own durability.** Each store publishes an immutable snapshot to
  the decode thread and mutates under its own lock on the keyboard thread.
- **The native layer owns the search.** Kotlin passes arrays and handles. It does
  not walk the trie, score a path, or allocate a frontier.
