**Scope.** The clipboard history and paste surface that WM Keyboard adds beside
Android's system clipboard: capture, classification, storage, paste, backup,
sync and the security boundary around them. **Not covered:** the user-facing
tool guide, which lives on [Clipboard manager](/tools/clipboard/), or the
settings screens themselves.

**Verified against** commit `c91fcba1a` plus the current uncommitted clipboard
fix work in this worktree (the inline autofill emulator test and its test
activity), on 2026-11-09. Line numbers move; class and function names are the
stable reference.

:::caution[The key invariant]
WM Keyboard is not an Android clipboard provider, and it does not try to become
one. Android owns the system clipboard in `system_server`. WM Keyboard is a
default input method when selected, so it can read clip changes and paste into
the focused field. It cannot replace the provider, and on Samsung devices it
cannot read or replace the separate One UI vendor history.
:::

## What the subsystem is

WM Keyboard keeps a searchable history of clips and offers them back through the
keyboard panel, the suggestion strip and the paste tools. The history is an
app-private JSON snapshot, not a database. Images are copied into app storage.
Files, folders and videos are recorded by URI and stay owned by the app that
shared them. Sensitive text is kept in process memory only.

The subsystem also owns three boundaries that are easy to miss:

- one write gate for every keyboard-originated system clipboard write;
- one sanitizer for untrusted ConfigBackup and sync bundles;
- one access gate that hides clipboard data before first unlock and while the
  keyguard is showing.

## What the subsystem is not

| Not this | Why |
|---|---|
| An Android clipboard provider | Android exposes no third-party clipboard role. `ClipboardManager` is a client of `system_server`. |
| The One UI clipboard history | Samsung stores its history in app-private vendor data with no public API. WM Keyboard cannot read, import, write or replace it. |
| A permanent record of every copy | Capture depends on the IME service process being alive and on WM Keyboard being the default IME or focused. |
| A keystore-backed secret vault | Sensitive clips live in process memory. Expiry makes them unreachable and unpasteable; it does not zero the memory. |
| A replacement for password managers | Inline autofill chips come from the active autofill service. The keyboard never receives the credential content. |

| Actor or system | Type | Responsibility | Failure behavior |
|---|---|---|---|
| Person using the keyboard | Person | Copies, searches, pins, edits and pastes clips | The panel shows an empty or reduced history; typing still works |
| Foreground app | External app | Calls `setPrimaryClip` and pastes through `ClipboardManager` | A read can return null; the keyboard drops that capture |
| Android clipboard service | System service in `system_server` | Owns the one primary clip and enforces the default-IME or focus read rule | WM Keyboard sees no change and cannot recover the missed clip |
| WM Keyboard IME | Software system, main process | Listens, classifies, stores, pastes and clears | Capture stops when the process dies or another IME holds the default role |
| Clipboard panel and strip | UI inside the IME | Search, pin, tag, edit, entity chips, combine, delete and paste | A locked device hides the panel because access is gated |
| App-private storage | Files under `filesDir/clipboard` | Holds `history.json` and copied image files | A corrupt or deleted snapshot is discarded; secrets are dropped with it |
| ConfigBackup and sync | User-initiated paths | Carry portable text, HTML and link clips | The sanitizer drops unsafe or malformed items instead of failing the whole restore |
| Active autofill service | External service, optional | Draws inline username, password and passkey chips | No provider means no chips; the keyboard does not invent credentials |
| Samsung One UI history | Vendor system data | Samsung's own clipboard history | Not readable, writable or replaceable by WM Keyboard |

## Evidence status

The architecture pages separate what the code does from what has been executed
on a device.

- **T6 is blocked.** The debug-only fake autofill provider cannot be activated
  for the instrumentation run in the current setup, and the inline chip test
  has an emulator session-ordering problem. The provider proves chip plumbing
  only; it proves nothing about passkeys.
- **T8 is unexecuted.** The real password-manager matrix (Bitwarden, Proton
  Pass, locked vault, passkey, incognito and Samsung One UI rows) has no local
  licensed APKs, test vaults or One UI hardware. The rows remain unexecuted.
- **The secure-window check is reported, not re-run here.** A prior API 36
  emulator run reported `FLAG_SECURE` on the IME window for a password field.
  The locked-boot and `bmgr` checks remain manual.

Nothing on these pages should be read as a T6 or T8 pass.
