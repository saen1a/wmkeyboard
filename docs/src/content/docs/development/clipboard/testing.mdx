## Commands

Run these from the repository root. Use the worktree whose branch you test.

```powershell
# T1: inline classifier and chip geometry
./gradlew :feature:ime:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.ime.InlineSuggestionClassifierTest" `
  --tests "com.wasimaster.wmkeyboard.ime.InlineChipClipTest"

# T2: manifest, backup rules, SDK levels and debug fixture separation
./gradlew :app:testIntlDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.app.ClipboardManifestAuditTest" `
  --tests "com.wasimaster.wmkeyboard.app.ClipboardBackupRulesTest"

# T3: restore boundary
./gradlew :app:testIntlDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.core.clipboard.ClipboardStoreTest"

# T3B: untrusted bundle and id deconfliction
./gradlew :core:content:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.core.clipboard.ClipboardSyncSanitizerTest"
./gradlew :core:settings:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.core.settings.SyncedClipboardIdsTest"

# T4: secure-window predicate
./gradlew :feature:ime:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.ime.SecureWindowTest"

# T5: API 36 Robolectric
./gradlew :feature:ime:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.ime.ClipboardApi36Test"

# Snapshot replacement, including the API 24/25 branch and the API 34 branch
./gradlew :core:common:testDebugUnitTest `
  --tests "com.wasimaster.wmkeyboard.core.util.SnapshotFileTest" `
  --tests "com.wasimaster.wmkeyboard.core.util.SnapshotFileApi34Test"

# The architecture rule for the one write gate
./gradlew :tools:architecture:test

# T7: emulator secure-window check
./gradlew :app:connectedIntlDebugAndroidTest `
  -Pandroid.testInstrumentationRunnerArguments.class=com.wasimaster.wmkeyboard.SecureWindowEmulatorTest

# T6: blocked. The class runs with its test ignored.
./gradlew :app:connectedIntlDebugAndroidTest `
  -Pandroid.testInstrumentationRunnerArguments.class=com.wasimaster.wmkeyboard.InlineAutofillEmulatorTest
```

Check the exit code, not only the summary. A test task that finds no matching
class can exit 0. For T6 that exit code is not evidence of a pass.

## What each unit covers

### T1: inline classifier

`InlineSuggestionClassifierTest` uses `InlineSuggestionMeta` only. It needs no
platform `InlineSuggestion` and never reads chip content. It covers zero
budgets, the autofill and platform lanes, the six and three caps, unknown
sources and the type tie-break inside the platform lane.

`InlineChipClipTest` covers chip geometry and the panel's chip placement. It is
a layout check, not a credential check.

### T2: manifest and backup audit

`ClipboardManifestAuditTest` binds the whole IME service element, so an
`android:process` attribute before `android:name` cannot slip past the check.
It also reads `method.xml`, `app/build.gradle.kts` and the debug manifest.

`ClipboardBackupRulesTest` reads both backup rule files and requires the whole
`clipboard` directory in cloud backup, device transfer and the legacy rules.
These are source audits, not a backup transport run.

### T3: restore boundary

`ClipboardStoreTest` covers the existing restore path: a legacy sensitive item
and image are cleaned, a legacy sensitive text is stripped from the file, a
corrupt snapshot is discarded, and an external reload merges or clears as
documented. It also covers snapshots, secrets, caps and media cleanup. The
restore cases are `legacySensitiveItemAndImageAreCleanedOnRestore` and
`legacySensitiveTextIsStrippedFromTheFileOnRestore`.

### T3B: sanitizer and ids

`ClipboardSyncSanitizerTest` starts from raw JSON, before the typed decoder. It
drops an item with `sensitive`, `imagePath`, `uriString`, `fileName` or
`linkPreview`, an item missing id or timestamp, an oversized text and a
secret-shaped text. A benign text item survives.

`SyncedClipboardIdsTest` writes a local file clip with id 1, applies a sync with
colliding text ids, and requires every id to stay unique. It also holds the
path lock while an uncoordinated external write lands and requires the sync to
read after the lock.

### T4: secure-window predicate

`SecureWindowTest` is the pure decision. It is true for a password field,
incognito, or the clipboard panel holding a secret. It is false for a clear
field and a clear panel. The service only applies what this predicate decides.

### T5: API 36 Robolectric

`ClipboardApi36Test` pins `@Config(sdk = [36])` on the class, rather than
inheriting the repository's API 34 default. A missing API 36 jar fails this run
instead of silently falling back to 34. It covers the sensitive flag, clipboard
extras and the device-protected palette context.

### T6: blocked fake provider

`InlineAutofillEmulatorTest` is intentionally ignored. API 36 creates the
`AutofillSession` before the IME window is visible, so the fill request has no
inline spec when the test can focus the field. The debug provider and its test
activity are still useful: they prove the fixtures stay out of release and they
are the basis for a rerun on a harness that wins the ordering.

The fake provider proves chip plumbing only. It proves nothing about passkeys,
vault state or a real password manager.

### T7: emulator secure window and manual checks

`SecureWindowEmulatorTest` reads the `fl=` attribute from
`dumpsys window windows` for the IME window while a password field has focus.
On API 36 the system prints the symbolic `SECURE` name rather than a raw hex
value. The recorded run on API 36 passed for a password field.

The harness changed in `2fb751ae1`. This page did not re-run the emulator test
after that change. Treat the pass as recorded for `cac37a30e`, not as a fresh
run of the current tree.

Manual checks that remain:

1. `adb shell bmgr enabled` shows whether backup is on.
2. `adb shell bmgr backupnow com.wasimaster.wmkeyboard` runs a backup with the
   configured transport. Inspect the transport or `dumpsys backup` for the
   `clipboard` path. With no transport configured, the static
   `ClipboardBackupRulesTest` is the fallback evidence.
3. Set a PIN, reboot, and stop at the first-unlock screen. Focus a text field
   there and try to open the clipboard panel. It must refuse or show an empty
   history. Unlock and confirm the history returns. This is a manual procedure;
   no automated locked-boot harness runs here.

Do not run a backup wipe or a factory reset on a device you need. A wipe is
destructive and is not part of this matrix.

### T8: unexecuted real-app matrix

The real password-manager matrix has no local evidence. There is no licensed
Bitwarden or Proton Pass APK, no test vault, no passkey provider and no One UI
hardware in this worktree. Every row stays unexecuted:

| Provider | Mode | Expected | Status |
|---|---|---|---|
| Bitwarden | Inline | Username and password chips appear in the autofill lane | Not executed |
| Bitwarden | Popup | No inline chip; the manager's own dropdown is the fallback | Not executed |
| Proton Pass | Inline | Chips appear on a version with an inline path | Not executed |
| Proton Pass | Popup | No inline chip; the manager's dropdown is the fallback | Not executed |
| Either | Locked vault | A locked-vault chip opens the manager rather than failing silently | Not executed |
| Either | Passkey field | The passkey chip opens the system or manager prompt; cancel leaves no stale chip | Not executed |
| Either | Incognito | Login chips stay available; platform smart replies are closed | Not executed |
| Samsung One UI | Vendor history | The vendor history is separate and cannot be read or replaced | Not executed |

## Docs gate

```powershell
cd docs
$env:CHECK_LINKS = "1"
npx astro build
```

The build validates every internal link when `CHECK_LINKS` is set. A broken
link fails the build instead of shipping. The build is not a substitute for the
test suites above.
