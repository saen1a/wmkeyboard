## Android and AOSP references

- [ClipboardManager](https://developer.android.com/reference/android/content/ClipboardManager)
  documents the default-IME and focus rule on `getPrimaryClip` and
  `hasPrimaryClip`.
- [ClipData](https://developer.android.com/reference/android/content/ClipData)
  documents the description extras used for the sensitive flag and the
  self-write token.
- [Secure clipboard handling](https://developer.android.com/privacy-and-security/risks/secure-clipboard-handling)
  covers the sensitive flag and the platform clipboard timeout.
- [AOSP ClipboardService](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/clipboard/ClipboardService.java)
  shows the default-IME check and the absence of a third-party provider role.
- [AutofillService](https://developer.android.com/reference/android/service/autofill/AutofillService)
  describes the provider side of the autofill framework.
- [InlineSuggestion](https://developer.android.com/reference/android/view/inputmethod/InlineSuggestion)
  documents the chip type the keyboard inflates from the active autofill service.
- [InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)
  documents `commitText` and the editor contract.
- [InputConnectionCompat](https://developer.android.com/reference/androidx/core/view/inputmethod/InputConnectionCompat)
  documents `commitContent`, the media path used for images and files.
- [FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider)
  documents the content URI the keyboard uses for copied images and media
  fallbacks.
- [Auto Backup](https://developer.android.com/guide/topics/data/autobackup)
  documents cloud backup, device transfer and the rule files.
- [Direct boot](https://developer.android.com/training/articles/direct-boot)
  explains device-protected storage and the first-unlock boundary.
- [Build.VERSION_CODES](https://developer.android.com/reference/android/os/Build.VERSION_CODES)
  is the API-level reference used by the snapshot fallback and the tests.

Samsung's vendor clipboard has no public API. The package name and file name in
these pages are reports, not code-verified facts. Do not treat them as an SDK
contract.

## Glossary

| Term | Meaning in this subsystem |
|---|---|
| Primary clip | The one `ClipData` Android's clipboard service holds in `system_server`. |
| Default IME | The input method package Android treats as the active keyboard. It may read the primary clip even when another app has focus. |
| Sensitive flag | `ClipData` description extra `EXTRA_IS_SENSITIVE`, set by the copying app. It is authoritative downward. |
| Heuristic | `ClipSensitivity`, the local check for password-shaped or code-shaped text. It can over-classify, and that cost is accepted. |
| Never save | The default handling. A sensitive clip is dropped at capture and never reaches memory or disk. |
| Keep | A memory-only handling. The secret stays in `SecretMemoryStore` for the normal history expiry. |
| Short-lived | A memory-only handling. The secret stays in `SecretMemoryStore` for a short timer. |
| Secret store | `SecretMemoryStore`, process memory only: no file, image, pin, tag or search index. |
| Write gate | `ClipboardWriteGate`, the only path for a keyboard-originated system clipboard write or clear. |
| Self-write token | A random one-shot value in the clip extras, kept by `SelfWriteLedger` for five seconds, so the listener skips the keyboard's own write. |
| Path lock | `SnapshotFile.withLock`, the per-file lock shared by the IME store and the ConfigBackup and sync writers. |
| Atomic replacement | Write a part file, fsync it, then replace the live file. No reader sees a half-written snapshot. |
| Sanitizer | `ClipboardSyncSanitizer`, the untrusted-bundle boundary for ConfigBackup and sync. It drops one bad item without failing the bundle. |
| Deconfliction | Renumbering incoming sync ids above every id in use, so the store does not collapse two clips. |
| Inline suggestion | A chip an autofill service returns through Android's inline autofill API. The keyboard inflates it; it does not read the credential value. |
| Direct boot | The boot state before the first unlock. Device-protected storage is available; credential-protected storage is not. |
| Device-protected storage | Storage available before first unlock. Clipboard history is not read from there. |
| ConfigBackup | The app's explicit backup and restore format, separate from Android Auto Backup and device transfer. |
| Device transfer | Android's device-to-device restore path. It uses the same exclusion rules as cloud backup. |
| Vendor history | Samsung One UI's own clipboard history. It is outside the AOSP clipboard and has no public API. |
| T6 | The blocked fake-provider instrumentation proof. |
| T8 | The unexecuted real password-manager and One UI matrix. |
