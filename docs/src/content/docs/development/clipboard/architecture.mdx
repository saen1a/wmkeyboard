## The one write path

Every keyboard-originated write goes through `ClipboardWriteGate`: panel copies,
tool copies, clean-text write-back, Clear, and Undo restores. The gate carries the
caller's sensitivity decision onto the clip, optionally stamps a self-write
token, and calls `setPrimaryClip`. `ClipboardWriteGate.clear` is the matching
clear path.

The architecture test
`keyboard clipboard writes go through the write gate` fails any new direct
`setPrimaryClip` or `clearPrimaryClip` call under `feature/ime` outside
`ClipboardWriteGate.kt`. That is the enforcement point for the one-writer rule.

The self-write token is a random identifier in `ClipData.description.extras`
with a private key. `SelfWriteLedger` keeps it for five seconds and consumes it
once. A write-back uses the token because the clean text is already in history.
It does not use the token to hide a stale write: the service first checks that
the system clipboard still holds the exact text it captured.

## Process model

| Fact | Evidence | Consequence |
|---|---|---|
| The IME service runs in the app main process | `WMKeyboardService` has no `android:process` attribute | Clipboard state is process-local and shares the app's lifecycle |
| The IME is not isolated | The manifest has no `isolatedProcess` for the service | It can use app-private files and normal Android services |
| The IME is direct-boot aware | `android:directBootAware="true"` | The service can start before first unlock, but clipboard data stays gated |
| `:crash`, `:semantic` and `:imagegen` are separate processes | Manifest entries for unrelated components | They do not own clipboard state and do not receive clipboard changes |
| Process death clears memory-only secrets | `SecretMemoryStore` has no file | A password retained with Keep or Short-lived is gone after the process dies |
| Destroy saves the clear history and removes the listener | `onDestroy` | A clean shutdown preserves clear clips; a kill can lose the last unsaved change |

The `:crash` process hosts the crash handler, `:semantic` hosts embedding
work and `:imagegen` hosts image generation. They are named here only to rule
them out: none of them is a clipboard container, and none changes the process
boundary above.

## State ownership

| State | Owner | Survives service destroy | Survives process death |
|---|---|---|---|
| Clear text, HTML and link clips | `ClipboardStore` over `history.json` | Yes, after `save` | Yes |
| Copied image bytes | `ClipboardStore` over `images/` | Yes | Yes |
| File, folder and video references | `ClipboardStore` over `history.json` | Yes | Yes, while the provider grant lasts |
| Retained secrets | `SecretMemoryStore` | No | No |
| Private keyboard copy | `KeyboardClipboard.held` | No | No |
| Self-write tokens | `SelfWriteLedger` | No | No |
| Panel snapshot | `KeyboardUiState.clipboardItems` | No | No |
| Capture counters | `ClipboardDiagnostics` | No | No |

## Failure modes

| Failure | What the subsystem does | What the user sees |
|---|---|---|
| Another app becomes the default IME | The listener may stay registered, but reads fail the platform rule | Copies are missed silently |
| The IME process is killed | No listener and no in-memory state until the service starts again | The history is stale and retained secrets are gone |
| `history.json` is corrupt | The store deletes the unreadable file and starts empty | Clear history is lost, not partially resurrected |
| An external writer deletes the history | `clearFromExternal` drops clear items and secrets | The panel is empty |
| An image copy exceeds the hard cap | The partial file is deleted and the clip is rejected | The image is not in history |
| A file URI grant has expired | Paste probes readability, removes the item and shows a toast | The clip disappears with an error message |
| A sync bundle is malformed | The sanitizer returns an empty bundle or drops one item | Other clips still restore |
| Inline autofill has no provider | No chips are produced | Typing still works; no credential is invented |
